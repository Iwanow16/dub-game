# ADR-0009: Клипы любой длины — сцены и потоковый режим
Статус: принято (дополняет ADR-0005)

Контекст: изначально клип ограничивался 5–90 с: он целиком загружается до записи (§11.3), дубли декодируются в `AudioBuffer`, лимиты тикетов рассчитаны на короткую запись. Игроки хотят озвучивать трейлеры игр (2–3 мин) и вырезки из сериалов (5–20 мин и дольше). Прямое снятие лимита ломает три вещи: предзагрузку (сотни мегабайт), декодирование дублей (минуты несжатого PCM на каждого игрока) и длительность раунда (7-минутный клип × 2 попытки × 6 игроков).

Решение:
1. **Сцены.** Манифест получает необязательный список `scenes` (`id`, `startMs`, `endMs`, `title`). Сцена — 5 с…2 мин, реплика не пересекает её границу. Клипу длиннее 90 с без разметки сцены назначаются автоматически (`autoScenes`: паузы между репликами около 45 с, предпочтительно на сетке ключевых кадров 2 с). Воркер режет для каждой сцены свой маленький пакет (видео-лестница, `bed`, постер, VTT): на сетке GOP — копированием потока, иначе перекодированием.
2. **Играемая единица.** Каталог разворачивается в `Playable` — клип целиком или одна его сцена. Настройка комнаты «Длинные клипы»: `scene` (по умолчанию: раунд = одна сцена) или `full` (клип целиком). Кандидаты раунда стараются быть из разных клипов; сыгранные сцены не повторяются.
3. **Потоковый режим.** Всё длиннее `STREAM_THRESHOLD_MS` = 2 мин клиент не загружает заранее: видео, фон и дубли играют через медиа-элементы, подключённые к Web Audio; старт по `playAt` на часах `AudioContext`, дрейф подтягивается `playbackRate`. Длиннее `LONG_TAKE_MS` = 3 мин — одна попытка без репетиции.
4. **Лимиты от длины.** Запись длинных клипов — 32 кбит/с; максимальный размер дубля в тикете (`max`) растёт с длиной клипа, сверху ограничен `DUB_MAX_MB`. Длина клипа после обрезки — до `CLIP_MAX_MINUTES` (по умолчанию 180). Время фазы записи считается из числа попыток и длины.
5. **Studio.** Для исходников длиннее 10 мин или больше 200 МБ редактор не скачивает файл, а берёт прокси по подписанной ссылке (`/drafts/:id/media-link`, 6 ч, по-прежнему за Cloudflare Access) с Range-запросами; волна рисуется из `peaks.bin` (пары min/max Int8, 100 в секунду), который делает воркер. Таймлайн масштабируется ×1…×64, новый шаг «Сцены».

Альтернативы: HLS/DASH для длинных клипов — тяжелее и не нужен при GOP 2 с и Range-запросах; запись длинного клипа кусками по репликам — ломает живое исполнение и синхронный просмотр; жёсткий лимит 3 мин — не решает задачу с сериалами.

Последствия: + любые клипы, короткие партии по сценам по-прежнему предзагружаются целиком; + старые клипы не меняются (сцены необязательны). − Больше места на клип (пакеты сцен), дольше обработка. − В потоковом режиме синхронность ~50–150 мс против ~10 мс у предзагрузки; на слабой сети возможны паузы буферизации.

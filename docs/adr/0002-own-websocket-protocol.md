# ADR-0002: `ws` + собственный протокол вместо Colyseus
Статус: принято

Контекст: игровой сервер — авторитетный конечный автомат с таймерами и синхронным стартом (§6.4). Состояние комнаты маленькое (≤ 26 участников).

Решение: библиотека `ws` и протокол из §6.4, сообщения C2S валидируются Zod. Сервер после каждого изменения отправляет каждому участнику **персональный полный снапшот** (`state`), а не JSON Patch: снапшот скрывает авторов дублей в анонимном режиме и содержит `myEntryId`. Часы синхронизируются NTP-подобным пингом, `playAt` задаётся в серверном времени.

Последствия: + полный контроль лимитов (16 КБ, 20 сообщ./с, 3 сокета на игрока), простая модель; − трафик больше, чем с патчами (~2–4 КБ на изменение — приемлемо); масштабирование на несколько инстансов потребует Redis pub/sub и sticky sessions (§15) — отдельный ADR на этапе 3.

Альтернативы: Colyseus (своя схема состояния и транспорт, сложнее персонализация снапшотов).

# ADR-0003: SQLite и файловое хранилище вместо PostgreSQL/Redis/MinIO на MVP
Статус: принято (пересмотреть на этапе 2–3)

Контекст: план (§6.2, §7) предполагает PostgreSQL, Redis и MinIO. Для вертикального среза и небольших инсталляций (домашний сервер, VPS 2 vCPU/4 ГБ) это три лишних сервиса, их бэкапы, секреты и обновления.

Решение:
- метаданные — **SQLite** (`node:sqlite`, WAL) в `DATA_DIR/db`; все запросы — в `packages/db`, схема повторяет §7;
- комнаты — **в памяти** игрового сервера (TTL 2 ч, как `room:{code}` в Redis);
- файлы — **том `DATA_DIR`**: `clips/` (отдаёт Caddy с immutable-кешем), `uploads/`, `dubs/` (TTL 24 ч);
- очередь медиа-задач — атомарный захват строки в SQLite вместо BullMQ. Воркеру не нужна сеть вообще (`network_mode: none`), что строже §22.6.

Последствия: + минимум движущихся частей, бэкап = `sqlite3 .backup` + tar клипов; − один инстанс игрового сервера (≥ 500 комнат по §15 — достаточно для MVP), нет горизонтального масштабирования.

План миграции: заменить реализацию `packages/db` на PostgreSQL (схема совместима), комнаты — на Redis, `DATA_DIR/clips` — на S3/R2 (меняется только `MEDIA_BASE_URL`, §21.7).
